# final

## Florent Code League

Версия для Florent находится в [florent/main.py](florent/main.py). Ядро раздаёт рабочим секторные задания через командное хранилище и расширяет отряды по мере роста доходов. Рабочие рассчитывают поток до ядра, прокладывают новые ветки при нехватке пропускной способности и восстанавливают разрывы. У действующих харвестеров они закрывают свободные порты и ставят Gunner или Spike при угрозе.

Ядро превращает доставленный Voltium в общие боеприпасы. Диверсанты ищут огневые позиции для Gunner и Sentinel, атакуют вражеское снабжение и используют Launcher для обхода препятствий и переправы через узкие разломы.

```powershell
pip install -r requirements.txt
fcode login
fcode maps sync
fcode run final final aland --watch
```

Карты лиги хранятся в `maps/florent`, повтор записывается в `florent.replay26`. Через браузер можно загрузить `final-florent.zip`. Для отправки исходника из терминала используйте `fcode submit bots/final/florent/main.py --name final`.

## Cambridge Battlecode

Точка входа движка — [main.py](main.py). Она передаёт управление
[finalbot/player.py](finalbot/player.py), где сущность получает свою роль.
Весь игровой код находится в `finalbot/`; другие боты для запуска не нужны.

```text
final/
├── main.py                   вход для cambc
├── finalbot/
│   ├── player.py             выбор роли и однократная инициализация
│   ├── core/                 стратегия ядра, спавн и состав отряда
│   ├── economy/
│   │   ├── builder/          координатор рабочего и его компоненты
│   │   ├── network/          пропускная способность и память сети
│   │   ├── refinery.py       строительство и восстановление переработки
│   │   ├── refinery_routes.py доступные участки и отдельные сырьевые линии
│   │   ├── mine_security.py  охрана портов шахты
│   │   ├── exploration.py    оценка разведки
│   │   ├── orders.py         экономические задания
│   │   └── policy.py         квоты рабочих и резерв ресурсов
│   ├── combat/
│   │   ├── intruder/         координатор диверсанта и его компоненты
│   │   ├── assault.py        выполнение осадного плана
│   │   ├── siege_planner.py  выбор снабжаемой огневой позиции
│   │   ├── hijack.py         использование вражеских транспортных потоков
│   │   └── ...               защитник, орудия и местная контрбатарея
│   ├── navigation/           поиск пути и доступ к месту строительства
│   ├── world/                карта, сущности и известные полосы огня
│   └── shared/               общие правила, геометрия, маркеры и бюджет CPU
├── checks/                   проверки, матчи и упаковка
└── VALIDATION.md              результаты проверок и ограничения
```

## С чего начать чтение

В [core/bot.py](finalbot/core/bot.py) задан порядок действий ядра.
[core/deployment.py](finalbot/core/deployment.py) отвечает за спавн, квоты и передачу
роли через маркер; [core/fleet.py](finalbot/core/fleet.py) проверяет состав отряда.

Для рабочего откройте [economy/builder/bot.py](finalbot/economy/builder/bot.py):
`__init__` хранит состояние роли, `run_turn` задаёт порядок действий. Длинные
операции вынесены в соседние файлы:

| Файл в `economy/builder/` | Ответственность |
| --- | --- |
| `observation.py` | Наблюдения, руда, маркеры и разведанный фронтир |
| `jobs.py` | Выбор задания, подключение шахты и завершение работы |
| `network.py` | Связность, загрузка линий и правила приёма ресурсов |
| `routing.py` | Планирование конвейерной ветви и переходов мостами |
| `construction.py` | Строительство, ремонт транспорта и расчистка руды |
| `scouting.py` | Выбор цели разведки и обход обслуживаемой сети |
| `movement.py` | Движение, подготовка дороги и уступание прохода |

У диверсанта такая же точка чтения:
[combat/intruder/bot.py](finalbot/combat/intruder/bot.py). Его компоненты:

| Файл в `combat/intruder/` | Ответственность |
| --- | --- |
| `observation.py` | Поиск ядер и учёт вражеских launcher |
| `exploration.py` | Разведка, возврат из тупика и обход ветвей |
| `movement.py` | Поиск подхода, дорожные шаги и обход стен |
| `launching.py` | Переброска через launcher и адресные маркеры |
| `targeting.py` | Выбор и строительство передового gunner |
| `supply_planning.py` | Источник боеприпасов и план маршрута снабжения |
| `supply_construction.py` | Строительство и восстановление снабжения |

Компоненты добавляют методы к роли через наследование. Они не создают отдельного
состояния и не переопределяют методы друг друга. Инициализация и порядок действий
остаются в `bot.py`; перенос не меняет игровую логику.

Рабочий выполняет ход в таком порядке; завершённое действие обычно заканчивает ход:

```text
обновить карту и задания
    → отразить непосредственную угрозу
    → продолжить проект переработки
    → восстановить транспорт и расчистить целевую руду
    → выбрать или продолжить подключение шахты
    → строить ветвь либо разведать доступный участок
```

Планировщики в `navigation/` и `refinery_routes.py` возвращают маршрут частями.
Рабочий хранит незавершённый поиск между ходами; исполнитель проверяет клетки
снова перед строительством, поскольку другой юнит мог изменить сеть.

Общие пороги находятся в [shared/constants.py](finalbot/shared/constants.py).
Локальные границы поиска и геометрические таблицы ролей — в их `settings.py`.
Карта и канонические координаты принадлежат [world/tile_cache.py](finalbot/world/tile_cache.py).

Клетка руды поддерживает дороги, транспорт и оружие. Планировщики отделяют
это правило движка от назначения клетки: выбранный источник шахты остаётся
свободным, действующая линия другого рабочего сохраняется. Для переработки
[refinery.py](finalbot/economy/refinery.py) собирает полный проект, а
[refinery_routes.py](finalbot/economy/refinery_routes.py) проверяет доступность
строительства и прокладывает раздельные подводы титана и сырого аксионита.

[economy/policy.py](finalbot/economy/policy.py) задаёт резерв для новой разведки
и бюджет атакующей группы. Решения о выделении денег отделены от выполнения
дорожного шага и от размещения нового юнита.

## Запуск и проверка

Из корня репозитория:

```powershell
cambc run final sota maps/arena.map26 --tle 2 --watch
.venv/Scripts/python.exe bots/final/checks/run_checks.py
.venv/Scripts/python.exe bots/final/checks/benchmark.py --opponents qualifier sota --maps arena default_small1 --jobs 2
.venv/Scripts/python.exe bots/final/checks/package_bot.py
```

Упаковщик и benchmark берут `main.py` вместе со всем пакетом `finalbot/`.
Проверки, пассивный соперник и локальные результаты в игровой архив не попадают.

Унаследованные тесты вне `final` не изменены. Их старые плоские пути обслуживает
`checks/legacy_tests.py` только в процессе проверки. Игровой код использует явные
импорты `finalbot.…` и не содержит таких перенаправлений.

Подробности матчей и ограничений локального измерения CPU — в
[VALIDATION.md](VALIDATION.md). Аудит переноса методов и сравнение контрольных
матчей сохраняются в [checks/results/structure_audit.json](checks/results/structure_audit.json).
